# Bellhop3D Environmental Data Contract (v0.24)

## Purpose

For each AOI, prepare a **source-resolved but unexecuted** inventory for
underwater acoustic Transmission Loss (TL). No acoustic coverage or TL estimates
are generated by this phase. The map layers, World Model numerical layers,
acoustic environmental layers and acoustic scenario remain separate products.

## Spatial and temporal domains

- **Visual AOI**: user-drawn geographical box and map extent.
- **Propagation domain**: user-selected buffer around AOI for data discovery.
  This is a first-pass approximation only. It must later contain the source
  position, every receiver and the relevant ray paths, plus enough margins for
  the chosen numerical model. Data jobs must span this domain, not just the
  original AOI.
- **Source resolution**: intrinsic grid spacing and observation quality, never
  the target analysis grid. Copernicus Mediterranean physics at ~4.2 km does not
  resolve 400 m-scale horizontal sound-speed changes.
- **Vertical domain**: depth positive downward; aligned reference for bathy,
  sea level, source and receiver depth. Pressure computed using appropriate
  latitude/reference and an approved seawater equation.
- **Simulation times**: choose one or more explicit UTC snapshots inside the
  dataset-valid time interval. Time window alone is not a simulation snapshot.

## Environmental data table

| Category | Variables | Initial candidate source | Gate |
|---|---|---|---|
| Terrain | Numeric bathymetry H(x,y) | Local hydrographic / EMODnet HR/DTM / GEBCO | Download actual numerical elevations, water mask, quality and vertical datum |
| Water column | T(x,y,z,t), S(x,y,z,t) | Copernicus Marine 3D or validated CTD | Verify pressure, salinity/temperature types, vertical levels, source resolution and timestamp |
| Acoustic | c(x,y,z,t), gradients | SVP measured or GSW conversion from T/S/pressure | Compute, cross-check, QA; avoid inventing horizontal detail |
| Bottom | Sediment class / bedrock / sediment thickness | EMODnet Geology + local surveys | Class alone does NOT provide acoustic speed, density or attenuation |
| Bottom acoustics | cp, density, attenuation, optional cs/shear attenuation, layering/roughness | Direct geoacoustic data or explicitly bounded priors | Set boundary model and material parameter uncertainty |
| Surface | Flat pressure-release or time-varying surface/top reflection | Explicit boundary choice, optional waves | Bulk significant height is not a spatially resolved instantaneous interface |
| Sea level | SSH/tide and reference | Copernicus Marine / local tide gauge | Align datums and validity |
| Waves | Hs, wave periods, mean direction / optional spectra | Copernicus Marine waves / buoy | Used only if surface model requires it |
| Currents | u,v and gradients | Copernicus Marine / ADCP | Context or moving-platform scenarios; **not** direct compulsory Bellhop3D vector inputs |
| Reference observations | CTD, SVP and other calibrated hydrography | Local profiles, in-situ services | Spatial/temporal matchup and bias/uncertainty checks |
| Volume absorption | Seawater attenuation assumptions | Approved frequency-dependent formulation | Declare source assumptions, frequency band and units |

For area-dependent geoacoustics, evaluate the bottom parameterization along ray
reflection paths, not just at source location. Frequency-dependent interface
scattering and roughness require additional sensitivity cases when appropriate.

## Scenario input, intentionally separate

Source lat/lon/depth, frequencies, transmit beam pattern; receiver positions and
depths, bearings and grid; coherent/incoherent choice, ray/beam sampling; time
snapshot and model type (Nx2D vs full 3D). No arbitrary values are silently
inserted. Full 3D only adds physical value when lateral bathymetry/SSP variation
is resolved and meaningful.

## Pipeline

1. **Discover** AOI-related numeric data and metadata, including observation
   footprints and time coverage.
2. **Acquire** immutable source snapshots for the expanded propagation domain.
3. **Normalize** CRS, sea-floor depths positive down, time and vertical datum,
   pressure, vertical levels and native support.
4. **Validate** water mask, missing cells, horizontal and vertical coverage,
   sediment classification/geoacoustics, in-situ comparison and source errors.
5. **Derive** sound speed c(x,y,z,t) with a recorded physical equation and
   processing parameters. Keep native grid distinct from computational grid.
6. **Configure** environmental boundaries, frequency, source/receiver geometry
   and the relevant 3D solver settings.
7. **Export native Bellhop3D** case.env and accompanying .bty, .ssp and optional
   .ati/.brc/.trc/.sbp according to actual boundary/scenario model choices.
8. **Run** Bellhop3D and parse .shd; convert to TL NetCDF/COG when appropriate,
   with provenance and sensitivity ensembles.
9. **Validate** against reference cases, then provide TL to downstream
   system/sensor effectiveness models. TL alone is NOT detection probability.

## Readiness status

A **SOURCE-RESOLVED** inventory is not an acquired or validated environment.
Every item currently begins as `NOT_ACQUIRED`, `NOT_VALIDATED`. The output
`readiness.status` is `NOT_READY` until all environmental, scenario and runtime
gates have passed. Nothing in this stage writes Bellhop input files or calls an
acoustic model. The downloadable JSON is intended as the execution hand-off.

For local high-resolution bathymetry, do **not** promote a survey footprint
selected only for the original AOI to the expanded propagation domain without
checking full coverage and compatible datum.
